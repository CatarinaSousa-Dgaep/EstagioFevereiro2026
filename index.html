📘 Módulo 1: Introdução ao Power BI

Conhece o ecossistema Power BI, os seus componentes e para que serve.

🔍 O que é o Power BI?

O Power BI é uma plataforma de Business Intelligence da Microsoft que permite ligar a diversas fontes de dados, transformá-los, modelá-los e criar relatórios e dashboards interativos. É utilizado por empresas em todo o mundo para apoiar a tomada de decisão baseada em dados.

O Power BI é composto por vários componentes que trabalham em conjunto:

🖥️ Power BI Desktop

Aplicação gratuita para Windows onde se criam os relatórios. Inclui o Power Query Editor para transformação de dados, a vista de modelo para relacionamentos e o canvas para visualizações.

É aqui que passarás a maior parte do tempo durante o estágio.

☁️ Power BI Service

Plataforma online (app.powerbi.com) onde se publicam e partilham relatórios. Permite colaboração, agendamento de atualização de dados e criação de dashboards a partir de múltiplos relatórios.

📱 Power BI Mobile

Aplicação disponível para iOS, Android e Windows. Permite visualizar relatórios e dashboards em qualquer lugar, receber alertas e anotar diretamente nos visuais.

⚙️ Fluxo de Trabalho Típico

O processo de trabalho no Power BI segue geralmente estas etapas:

Etapa Descrição Ferramenta
1. Obter Dados Ligar a fontes (Excel, SQL, Web, APIs, etc.) Power Query
2. Transformar Limpar, formatar e preparar os dados Power Query Editor
3. Modelar Criar relações entre tabelas, definir hierarquias Model View
4. Visualizar Criar gráficos, tabelas e visuais interativos Report View
5. Publicar Partilhar com a equipa no Power BI Service Power BI Service

🎯 Interface do Power BI Desktop

O Power BI Desktop tem três vistas principais, acessíveis pelos ícones à esquerda:

  • Report View (📊): Onde crias os visuais e montas o layout do relatório. É o canvas principal.
  • Data View (📋): Permite visualizar os dados carregados em formato tabular. Útil para verificar transformações.
  • Model View (🔗): Mostra o diagrama de relacionamentos entre tabelas. Essencial para a modelação de dados.
📌 Dica: Alterna frequentemente entre as três vistas durante o desenvolvimento para garantir que os dados e relações estão corretos.

🔄 Módulo 2: Power Query

Aprende a importar, limpar e transformar dados antes de os analisar.

🔍 O que é o Power Query?

O Power Query é o motor de ETL (Extract, Transform, Load) integrado no Power BI. Permite ligar a centenas de fontes de dados e aplicar transformações sem alterar os dados originais. Todas as transformações são gravadas como "passos" (steps) que são reaplicados automaticamente sempre que os dados são atualizados.

✅ O Power Query usa a linguagem M (também chamada Power Query Formula Language). Não precisas de a escrever manualmente — a maioria das operações é feita com cliques na interface.

📥 Fontes de Dados Suportadas

Ficheiros
  • Excel (.xlsx, .xls)
  • CSV / TXT
  • JSON
  • XML
  • PDF
  • Pasta (múltiplos ficheiros)
Bases de Dados
  • SQL Server

🛠️ Transformações Essenciais

Estas são as operações que mais usarás no dia-a-dia:

Operação O que faz Exemplo
Remover Colunas Elimina colunas desnecessárias Remover coluna "ID_interno"
Filtrar Linhas Remove linhas que não interessam Filtrar vendas > 0
Alterar Tipo Define o tipo de dados correto Texto → Data, Texto → Número
Substituir Valores Troca valores específicos "N/A" → null
Dividir Coluna Separa uma coluna em várias "Lisboa, Portugal" → Cidade + País
Agrupar Por Agrega dados por categoria Total de vendas por região
Merge Queries Junta duas tabelas (tipo JOIN SQL) Vendas + Clientes por ID_Cliente
Append Queries Empilha tabelas (tipo UNION SQL) Vendas_2023 + Vendas_2024
Coluna Personalizada Cria nova coluna com fórmula M [Preço] * [Quantidade]
Unpivot Columns Transforma colunas em linhas Meses como colunas → coluna "Mês"

📝 Exemplo Prático: Linguagem M

Embora a maioria das operações seja via interface gráfica, é útil entender o código M gerado. Aqui está um exemplo completo:

Linguagem M let // 1. Ligar à fonte de dados Fonte = Excel.Workbook( File.Contents("C:\Dados\Vendas2024.xlsx"), null, true ), // 2. Selecionar a tabela Tabela = Fonte{[Item="Vendas", Kind="Sheet"]}[Data], // 3. Promover cabeçalhos Cabecalhos = Table.PromoteHeaders(Tabela, [PromoteAllScalars=true]), // 4. Alterar tipos de dados Tipos = Table.TransformColumnTypes(Cabecalhos, { {"Data", type date}, {"Valor", type number}, {"Produto", type text}, {"Quantidade", Int64.Type} }), // 5. Filtrar linhas nulas Filtrado = Table.SelectRows(Tipos, each [Valor] <> null and [Valor] > 0), // 6. Adicionar coluna calculada ComTotal = Table.AddColumn(Filtrado, "Total", each [Valor] * [Quantidade], type number), // 7. Remover colunas desnecessárias Limpo = Table.RemoveColumns(ComTotal, {"ColunaTemp", "ID_Antigo"}) in Limpo

⚠️ Boas Práticas no Power Query

  • Nomeia os passos: Clica com o botão direito nos Applied Steps e renomeia para algo descritivo (ex: "Filtrar vendas positivas").
  • Remove colunas cedo: Quanto menos dados carregares, mais rápido será o modelo.
  • Define tipos de dados sempre: Evita erros em cálculos DAX posteriores.
  • Usa "Close & Apply": Só quando terminares todas as transformações.
  • Desativa o carregamento de tabelas auxiliares que não precisam ir para o modelo (botão direito → "Enable Load" desativado).
  • Evita colunas com erros: Verifica sempre o indicador de qualidade no cabeçalho de cada coluna.
⚠️ Atenção: Nunca alteres dados diretamente no Data View do Power BI. Todas as transformações devem ser feitas no Power Query para serem reprodutíveis.

🗂️ Módulo 3: Modelação de Dados

Aprende a estruturar o modelo de dados com relações, esquema em estrela e boas práticas.

🔍 O que é Modelação de Dados?

A modelação de dados é o processo de organizar e estruturar as tabelas do teu modelo para que o Power BI consiga calcular e agregar informação de forma eficiente. Um bom modelo é a base de qualquer relatório rápido e fiável.

O objetivo é criar relações lógicas entre tabelas para que, ao interagir com um visual, todos os outros reajam corretamente (cross-filtering).

⭐ Esquema em Estrela (Star Schema)

O padrão recomendado pela Microsoft para Power BI. Consiste em:

Tipo de Tabela Função Exemplos Características
Tabela de Factos Contém os eventos/transações (dados numéricos) Vendas, Encomendas, Pagamentos Muitas linhas, colunas numéricas + chaves estrangeiras
Tabela de Dimensão Contém atributos descritivos (contexto) Clientes, Produtos, Datas, Lojas Menos linhas, colunas descritivas + chave primária
✅ Regra de ouro: As dimensões filtram os factos. As setas de relação devem apontar da dimensão para o facto (1 para muitos).
Diagrama Conceptual [DimData] ──1:N──┐ │ [DimProduto] ──1:N──┤ ├── [FactVendas] [DimCliente] ──1:N──┤ │ [DimLoja] ──1:N──┘

🔗 Tipos de Relações

Cardinalidade Descrição Uso Comum
1:N (Um para Muitos) Uma linha da dimensão corresponde a muitas no facto O mais comum — ex: 1 produto → muitas vendas
1:1 (Um para Um) Uma linha corresponde a exatamente uma noutra tabela Raro — ex: Funcionário → Detalhe de contrato
N:N (Muitos para Muitos) Múltiplas correspondências em ambos os lados Evitar se possível — usar tabela-ponte
⚠️ Atenção: Relações N:N podem gerar resultados inesperados. Sempre que possível, reestrutura os dados para usar relações 1:N.

📅 Tabela de Datas (Essencial)

Toda a análise temporal no Power BI necessita de uma tabela de datas dedicada. Sem ela, funcionalidades como YTD, comparação com período anterior e hierarquias temporais não funcionam corretamente.

DAX — Criar Tabela de Datas DimCalendario = ADDCOLUMNS( CALENDARAUTO(), "Ano", YEAR([Date]), "Mês Nº", MONTH([Date]), "Mês Nome", FORMAT([Date], "MMMM"), "Mês Abrev", FORMAT([Date], "MMM"), "Trimestre", "Q" & FORMAT([Date], "Q"), "Dia da Semana", WEEKDAY([Date], 2), "Nome Dia", FORMAT([Date], "dddd"), "Ano-Mês", FORMAT([Date], "YYYY-MM"), "Semana do Ano", WEEKNUM([Date], 2) )
📌 Depois de criar a tabela, marca-a como "Date Table" em: Table Tools → Mark as Date Table → seleciona a coluna de data.

⚙️ Boas Práticas de Modelação

  • Usa sempre esquema em estrela — evita relações entre tabelas de factos.
  • Esconde colunas-chave (IDs) — o utilizador não precisa de ver ID_Produto nos visuais.
  • Cria hierarquias — ex: Ano → Trimestre → Mês → Dia na tabela de datas.
  • Evita relações bidirecionais — só usa cross-filter "Both" quando estritamente necessário.
  • Minimiza colunas calculadas — prefere medidas DAX (calculadas em tempo de query).
  • Remove tabelas desnecessárias — tudo o que não é usado desperdiça memória.
  • Organiza as medidas numa tabela separada (ex: "_Medidas") para manter tudo limpo.

🧮 Módulo 4: DAX (Data Analysis Expressions)

Domina a linguagem de fórmulas do Power BI para criar medidas e colunas calculadas.

🔍 O que é DAX?

DAX (Data Analysis Expressions) é a linguagem de fórmulas do Power BI. É semelhante às fórmulas do Excel, mas muito mais poderosa pois opera sobre tabelas e colunas inteiras, compreendendo o contexto de filtro dos visuais.

📌 DAX é usado para criar Medidas (calculadas em tempo de execução) e Colunas Calculadas (calculadas ao carregar os dados). Prefere sempre medidas quando possível.

📐 Medida vs Coluna Calculada

Característica Medida Coluna Calculada
Quando calcula Em tempo de query (dinâmica) Ao carregar/atualizar dados
Memória Não ocupa espaço extra Ocupa espaço no modelo
Contexto de filtro Reage aos filtros e slicers Valor fixo por linha
Uso típico Agregações, KPIs, ratios Categorização, colunas derivadas
Recomendação ⭐ Usar sempre que possível Usar só quando necessário

📊 Funções DAX Essenciais

📈 Funções de Agregação ▼
// Soma total de vendas Total Vendas = SUM(FactVendas[Valor]) // Contagem de linhas Nº Transações = COUNTROWS(FactVendas) // Contagem de valores distintos Nº Clientes = DISTINCTCOUNT(FactVendas[ClienteID]) // Média Ticket Médio = AVERAGE(FactVendas[Valor]) // Mínimo e Máximo Primeira Venda = MIN(FactVendas[Data]) Última Venda = MAX(FactVendas[Data])
🔧 CALCULATE — A função mais importante ▼

CALCULATE modifica o contexto de filtro de uma expressão. É a função mais poderosa e usada em DAX.

// Vendas filtradas por categoria Vendas Eletrónicos = CALCULATE( SUM(FactVendas[Valor]), DimProduto[Categoria] = "Eletrónicos" ) // Vendas do ano anterior Vendas Ano Anterior = CALCULATE( [Total Vendas], SAMEPERIODLASTYEAR(DimCalendario[Date]) ) // Vendas acumuladas no ano (YTD) Vendas YTD = CALCULATE( [Total Vendas], DATESYTD(DimCalendario[Date]) ) // Remover todos os filtros de uma tabela Vendas Totais Sem Filtro = CALCULATE( [Total Vendas], ALL(DimProduto) )
📅 Time Intelligence (Análise Temporal) ▼

Requerem uma tabela de datas marcada corretamente.

// Acumulado no ano Vendas YTD = TOTALYTD([Total Vendas], DimCalendario[Date]) // Acumulado no mês Vendas MTD = TOTALMTD([Total Vendas], DimCalendario[Date]) // Mesmo período do ano passado Vendas LY = CALCULATE([Total Vendas], SAMEPERIODLASTYEAR(DimCalendario[Date])) // Variação percentual vs ano anterior Var% YoY = VAR _atual = [Total Vendas] VAR _anterior = [Vendas LY] RETURN IF(_anterior = 0, BLANK(), DIVIDE(_atual - _anterior, _anterior)) // Últimos 30 dias Vendas Últimos 30d = CALCULATE( [Total Vendas], DATESINPERIOD(DimCalendario[Date], MAX(DimCalendario[Date]), -30, DAY) )
🧩 Funções de Tabela e Iteração ▼
// SUMX — soma iterativa (linha a linha) Receita Total = SUMX( FactVendas, FactVendas[Quantidade] * FactVendas[PreçoUnitário] ) // FILTER — filtra uma tabela Vendas Grandes = CALCULATE( COUNTROWS(FactVendas), FILTER(FactVendas, FactVendas[Valor] > 1000) ) // RANKX — ranking Rank Produto = RANKX( ALL(DimProduto[NomeProduto]), [Total Vendas], , DESC, Dense ) // TOPN — top N resultados Top 5 Produtos = CONCATENATEX( TOPN(5, ALL(DimProduto[NomeProduto]), [Total Vendas], DESC), DimProduto[NomeProduto], ", " )
🔀 Funções Lógicas e Texto ▼
// IF — condicional Classificação = IF([Total Vendas] > 100000, "Alto", IF([Total Vendas] > 50000, "Médio", "Baixo")) // SWITCH — múltiplas condições (mais limpo que IF encadeado) Segmento = SWITCH(TRUE(), [Total Vendas] > 100000, "🟢 Premium", [Total Vendas] > 50000, "🟡 Standard", [Total Vendas] > 10000, "🟠 Básico", "🔴 Baixo" ) // DIVIDE — divisão segura (evita erro de divisão por zero) Margem % = DIVIDE([Lucro], [Receita], 0) // FORMAT — formatar valores Vendas Formatadas = FORMAT([Total Vendas], "#,##0.00 €") // CONCATENATE / operador & Nome Completo = DimCliente[Nome] & " " & DimCliente[Apelido]

💡 Boas Práticas em DAX

  • Usa variáveis (VAR): Tornam o código legível e evitam recalcular expressões.
  • Usa DIVIDE() em vez de /: Evita erros de divisão por zero.
  • Prefere medidas a colunas calculadas: São mais eficientes e reativas aos filtros.
  • Organiza medidas numa pasta: Cria uma tabela vazia "_Medidas" e agrupa-as por categoria.
  • Formata o código: Usa indentação e quebras de linha para DAX complexo. Experimenta o site daxformatter.com.
  • Testa com tabelas e cards simples: Antes de usar numa visualização complexa, verifica o resultado num Card ou Table simples.

📈 Módulo 5: Visualizações

Cria dashboards profissionais e interativos com as melhores práticas de visualização de dados.

🔍 Princípios de Boa Visualização

Um bom dashboard não é apenas bonito — é funcional, claro e orientado à decisão. Segue estes princípios fundamentais:

  • Menos é mais: Evita sobrecarregar a página. 5-8 visuais por página é o ideal.
  • Hierarquia visual: O KPI mais importante deve estar no topo-esquerda (onde o olho vai primeiro).
  • Consistência: Usa as mesmas cores para representar as mesmas categorias em todo o relatório.
  • Contexto: Todos os números devem ter unidades, títulos descritivos e período temporal.
  • Acessibilidade: Usa cores acessíveis para daltónicos. Evita vermelho/verde juntos.

📊 Quando Usar Cada Visual

Visual Melhor Para Exemplo
Card Mostrar um único KPI Total de vendas, nº de clientes
Gráfico de Barras Comparar categorias Vendas por região
Gráfico de Linhas Mostrar tendências ao longo do tempo Evolução mensal de receita
Gráfico de Colunas Empilhadas Comparar partes de um todo ao longo de categorias Vendas por produto e região
Gráfico Circular / Donut Mostrar proporções (max 5-6 fatias) Quota de mercado
Tabela / Matriz Detalhes e drill-down Lista de transações, pivot tables
Mapa Dados geográficos Vendas por país/cidade
KPI Visual Mostrar progresso vs objetivo Vendas atuais vs meta
Gauge Mostrar valor numa escala % de objetivo atingido
Treemap Hierarquias com proporções Vendas por categoria > subcategoria
Scatter Plot Correlação entre 2 métricas Preço vs Quantidade vendida

🎨 Formatação e Design

  • Tema personalizado: Vai a View → Themes → Customize para definir cores, fontes e estilos globais. Podes importar um ficheiro .json de tema.
  • Fundo da página: Usa um wallpaper ou fundo com opacidade reduzida para dar profundidade.
  • Títulos dinâmicos: Usa medidas DAX nos títulos para que mudem conforme os filtros selecionados.
  • Ícones e imagens: Adiciona o logo da empresa e ícones para melhorar a identidade visual.
  • Bordas e sombras: Ativa bordas arredondadas e sombras subtis nos visuais para um look moderno.
DAX — Título Dinâmico Título Dinâmico = VAR _regiao = SELECTEDVALUE(DimLoja[Região], "Todas as Regiões") VAR _ano = SELECTEDVALUE(DimCalendario[Ano], "Todos os Anos") RETURN "Vendas — " & _regiao & " — " & _ano

🔘 Interatividade

O Power BI permite criar experiências interativas poderosas:

  • Slicers (Segmentadores): Filtros visuais que o utilizador pode manipular. Usa slicers de data, dropdown e lista.
  • Cross-filtering: Ao clicar num visual, os outros reagem. Configura em Format → Edit Interactions.
  • Drill-through: Permite navegar para uma página de detalhe ao clicar com botão direito num ponto de dados.
  • Bookmarks: Guarda estados de filtros e navegação. Útil para criar menus e navegação entre páginas.
  • Tooltips personalizados: Cria uma página-tooltip com visuais que aparecem ao passar o rato sobre um ponto de dados.
  • Botões de navegação: Adiciona botões para navegar entre páginas do relatório.

🚀 Módulo 6: Publicação e Partilha

Publica os teus relatórios no Power BI Service e partilha-os com a equipa.

🔍 Do Desktop para a Cloud

Depois de criares o relatório no Power BI Desktop, o passo seguinte é publicá-lo no Power BI Service (app.powerbi.com) para que outros possam aceder, interagir e colaborar.

📌 Precisas de uma conta organizacional (email corporativo ou educacional) com licença Power BI Pro ou Premium Per User para publicar e partilhar.

📤 Como Publicar

O processo de publicação é simples e direto:

Passo Ação Detalhes
1 Guardar o ficheiro .pbix Ctrl+S — garante que todas as alterações estão guardadas
2 Clicar em "Publish" Home → Publish (canto superior direito)
3 Escolher o Workspace Seleciona o workspace de destino (ex: "My Workspace" ou um workspace partilhado)
4 Aguardar o upload O ficheiro é carregado para a cloud da Microsoft
5 Abrir no browser Clica no link para abrir o relatório no Power BI Service

🏢 Workspaces

Os Workspaces são espaços de colaboração no Power BI Service onde equipas partilham relatórios, datasets e dashboards.

Tipo Descrição Uso
My Workspace Espaço pessoal, só tu vês Testes e desenvolvimento pessoal
Workspace Partilhado Espaço de equipa com roles Colaboração e partilha com a equipa

Roles disponíveis num workspace:

  • Admin: Controlo total — gerir membros, eliminar conteúdo, publicar apps.
  • Member: Pode publicar e editar conteúdo, mas não gerir membros.
  • Contributor: Pode criar e editar conteúdo, mas não publicar apps.
  • Viewer: Apenas pode visualizar — sem edição.

📊 Dashboards vs Relatórios no Service

Característica Relatório (Report) Dashboard
Origem Criado no Power BI Desktop Criado no Power BI Service
Páginas Múltiplas páginas Página única com tiles (pins)
Fontes Um único dataset Pode combinar tiles de múltiplos relatórios
Interatividade Cross-filtering, slicers, drill-through Clique leva ao relatório de origem
Alertas Não disponível Pode configurar alertas em cards numéricos

🔄 Atualização de Dados

Depois de publicar, podes configurar a atualização automática dos dados:

  • Scheduled Refresh: Agenda atualizações até 8x por dia (Pro) ou 48x por dia (Premium).
  • Gateway: Se os dados estão on-premises (ex: SQL Server local), precisas instalar o On-premises Data Gateway para que o Service consiga aceder à fonte.
  • DirectQuery: Em vez de importar, consulta os dados em tempo real. Útil para dados muito grandes ou que mudam constantemente.
✅ Dica: Para configurar o refresh, vai ao workspace → Dataset → Settings → Scheduled Refresh.

🔒 Row-Level Security (RLS)

O RLS permite restringir quais dados cada utilizador vê, com base em regras definidas no modelo:

DAX — Regra RLS por Região // Criada em Modeling → Manage Roles → New Role // Tabela: DimLoja // Expressão de filtro: [Região] = USERPRINCIPALNAME() // Ou para um utilizador específico: [Região] = "Norte"

Depois de definir os roles, atribui utilizadores a cada role no Power BI Service (workspace → Dataset → Security).

🏋️ Exercícios Práticos

Põe em prática o que aprendeste com estes desafios progressivos.

🟢 Exercício 1 — Relatório de Vendas Básico

Nível: Iniciante  |  Módulos: 1, 2, 5

Objetivo: Criar um relatório simples com dados de vendas.

Passos:

  1. Descarrega o ficheiro de exemplo "Contoso Sales" da Microsoft (ou usa um Excel com dados de vendas).
  2. Importa os dados no Power BI Desktop.
  3. No Power Query: remove colunas desnecessárias, verifica tipos de dados, filtra valores nulos.
  4. Cria uma página com: 3 Cards (Total Vendas, Nº Transações, Ticket Médio), 1 Gráfico de Linhas (vendas por mês), 1 Gráfico de Barras (vendas por categoria).
  5. Adiciona um slicer de data.

🟡 Exercício 2 — Modelo em Estrela + DAX

Nível: Intermédio  |  Módulos: 3, 4

Objetivo: Estruturar um modelo em estrela e criar medidas DAX avançadas.

Passos:

  1. Usa pelo menos 4 tabelas: FactVendas, DimProduto, DimCliente, DimCalendario.
  2. Cria a tabela DimCalendario com DAX (CALENDARAUTO + ADDCOLUMNS).
  3. Estabelece relações 1:N entre dimensões e facto.
  4. Cria estas medidas: Total Vendas, Vendas YTD, Vendas LY, Variação % YoY, Rank de Produto.
  5. Organiza as medidas numa tabela "_Medidas".

🔴 Exercício 3 — Dashboard Profissional Completo

Nível: Avançado  |  Módulos: Todos

Objetivo: Criar um dashboard completo, profissional e publicá-lo.

Passos:

  1. Importa dados de pelo menos 2 fontes diferentes (ex: Excel + CSV).
  2. Aplica transformações completas no Power Query (merge, unpivot, colunas calculadas).
  3. Estrutura um modelo em estrela com pelo menos 4 dimensões.
  4. Cria pelo menos 10 medidas DAX (incluindo Time Intelligence e RANKX).
  5. Desenha um dashboard com 3 páginas: Resumo Executivo, Análise Detalhada, Detalhe por Cliente.
  6. Implementa: tema personalizado, drill-through, tooltips personalizados, bookmarks para navegação.
  7. Configura pelo menos uma regra de RLS.
  8. Publica no Power BI Service e partilha com um colega.

📖 Glossário

Termos e conceitos essenciais do universo Power BI.

Append

Operação no Power Query que empilha (une verticalmente) duas ou mais tabelas com a mesma estrutura. Equivale ao UNION em SQL.

Bookmark

Funcionalidade que guarda um estado específico do relatório (filtros, visibilidade, página). Usado para criar navegação interativa.

CALCULATE

Função DAX mais importante. Avalia uma expressão num contexto de filtro modificado. Sintaxe: CALCULATE(expressão, filtro1, filtro2, ...).

Cardinalidade

Define o tipo de relação entre duas tabelas: 1:1, 1:N (um para muitos) ou N:N (muitos para muitos).

Coluna Calculada

Coluna adicionada a uma tabela via DAX, calculada ao carregar os dados. O valor é fixo por linha e ocupa memória no modelo.

Contexto de Filtro

Conjunto de filtros ativos que determinam quais dados são visíveis para uma expressão DAX. Inclui filtros de visuais, slicers, página e relatório.

Cross-filtering

Comportamento onde a seleção num visual filtra automaticamente os outros visuais na mesma página. Configurável via Edit Interactions.

DAX

Data Analysis Expressions — linguagem de fórmulas do Power BI para criar medidas, colunas calculadas e tabelas calculadas.

Dataset

Conjunto de dados publicado no Power BI Service. Contém tabelas, relações, medidas e metadados. Base para relatórios e dashboards.

DirectQuery

Modo de conexão que consulta a fonte de dados em tempo real, sem importar. Útil para dados muito grandes ou que mudam frequentemente.

Drill-through

Funcionalidade que permite navegar de um visual para uma página de detalhe, passando o contexto de filtro do item clicado.

ETL

Extract, Transform, Load — processo de extrair dados de fontes, transformá-los e carregá-los no destino. O Power Query é a ferramenta ETL do Power BI.

Esquema em Estrela

Padrão de modelação recomendado: uma tabela de factos central rodeada por tabelas de dimensão ligadas por relações 1:N.

Gateway

Software que permite ao Power BI Service aceder a dados on-premises (dentro da rede da empresa). Necessário para scheduled refresh de fontes locais.

Implicit Measure

Agregação automática criada pelo Power BI ao arrastar um campo numérico para um visual. Recomenda-se substituir por medidas explícitas.

Linguagem M

Power Query Formula Language — linguagem funcional usada pelo Power Query. Cada transformação gera código M nos bastidores.

Medida (Measure)

Cálculo DAX avaliado em tempo de query. Reage ao contexto de filtro e não ocupa espaço extra no modelo. Preferível a colunas calculadas.

Merge

Operação no Power Query que junta duas tabelas por uma coluna-chave comum. Equivale ao JOIN em SQL.

RLS (Row-Level Security)

Mecanismo de segurança que filtra os dados visíveis por utilizador com base em regras DAX definidas no modelo.

Scheduled Refresh

Agendamento automático de atualização de dados no Power BI Service. Até 8x/dia (Pro) ou 48x/dia (Premium).

Slicer

Visual de filtro interativo que permite ao utilizador selecionar valores para filtrar os dados na página ou relatório.

Tabela de Factos

Tabela central do modelo que contém transações/eventos (dados numéricos). Tem muitas linhas e chaves estrangeiras para as dimensões.

Tabela de Dimensão

Tabela descritiva que dá contexto aos factos. Contém atributos como nomes, categorias, datas e localizações.

Time Intelligence

Conjunto de funções DAX para análise temporal: YTD, MTD, QTD, SAMEPERIODLASTYEAR, DATESINPERIOD, etc. Requer tabela de datas marcada.

Tooltip

Informação que aparece ao passar o rato sobre um ponto de dados. Pode ser personalizada com uma página dedicada contendo visuais.

Unpivot

Transformação no Power Query que converte colunas em linhas. Útil para normalizar dados que estão em formato "wide" (ex: meses como colunas).

Workspace

Espaço colaborativo no Power BI Service onde equipas organizam e partilham relatórios, datasets e dashboards.
